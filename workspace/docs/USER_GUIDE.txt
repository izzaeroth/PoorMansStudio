Take Review library organization. In current project format 15, Active and Archived reviews can store searchable Tags and descriptive Notes. Format-14 review-library projects remain load-compatible; the new Cross-Pass Notes setting safely defaults to Off when it is absent. The Take Review Manager provides case-insensitive Search across track name, review name, tags, and notes plus Show = All / Active / Archived. Multiple search words use AND matching. The copy receives a new stable review-session ID and deterministic Copy / Copy 2 / Copy 3 naming while retaining the source passes, comp map, Boundary Notes, Sustain Pedal/CC64 data, Tags, and Notes. Active Take Review snapshots. Snapshot Active (Take Review Manager) and Snapshot (MIDI TAKE REVIEW row) save an independent Archived checkpoint of the current Active review without resolving or replacing the Active editor. Snapshots receive a new stable review-session ID and deterministic Snapshot / Snapshot 2 / Snapshot 3 naming, preserve the complete saved review payload, and leave Pending Takes plus project MIDI notes unchanged.
Cross-track Archived Take Review transfer. Copy to Track creates an independent Archived copy on a different MIDI track with a fresh review-session ID. Move to Track transfers the same logical Archived review to a different MIDI track while preserving its stable review-session ID; destination ownership is created before the source archive is removed, and Active reviews, Pending Takes, project MIDI notes, and Undo Take history remain unchanged.

1. Quick Start
==============
Poor Man's Studio is a local Windows desktop music workstation for building and rendering small to medium music projects without requiring a full commercial DAW. It focuses on practical import, edit, preview, record, and render workflows using local tools such as FluidSynth, sfizz, FFmpeg, and optional VST3 and CLAP plugins.
NOTE: The most important workflow rule is simple: Project Defaults affect new/imported MIDI tracks; Apply Track Settings commits changes to the selected track; Save Project commits project metadata and attached staged AudioClip media.

Fastest path from import to rendered audio
------------------------------------------
Step | Action | Why it matters
--- | --- | ---
1 | Choose project defaults: backend, library, instrument, base name, output format, sample rate, and channels. | These defaults are copied into future imported or newly added MIDI tracks.
2 | Click Apply Project Defaults. | This is the commit point for project-level default choices.
3 | Start from MusicXML, MXL, MIDI, audio, or an existing .mwproj project. | Poor Man's Studio creates tracks and sequences from the chosen source.
4 | Choose a track and adjust instrument, VST Effect slots, mute/solo, and volume. | These are selected-track settings, not project defaults.
5 | Click Apply Track Settings. | This commits the selected track controls, including VST Effect dropdowns, Enable, and Bypass.
6 | Preview the track, sequence, region, or full project. | Preview renders temporary files so you can hear the result before final export.
7 | Save Project. | This writes .mwproj metadata and moves attached staged AudioClip media into the saved project folder.
8 | Render/export final audio or MIDI. | The render path uses saved track assignments and enabled effect chains.

Commit points at a glance
-------------------------
Change type | Commit button | Common mistake to avoid
--- | --- | ---
Project default backend or instrument | Apply Project Defaults | Expecting project defaults to retroactively change existing tracks.
Selected-track instrument, volume, mute, solo, or VST Effect slot controls | Apply Track Settings | Changing a dropdown or checkbox and then rendering without applying track settings.
Open VST editor parameter changes | Apply Changes inside the VST editor | Closing the editor before capturing parameter changes.
Imported or recorded AudioClip media staged in temp | Save Project | Expecting Import Audio or Save / Apply recording to create a project folder before the project is saved.
Unwanted temporary previews or abandoned staging sessions | Clean Temp | Deleting workspace files manually while a project is open.

2. Core Concepts
================

Project
-------
A project is the full song/session state: tracks, sequences, note data, AudioClip references, instrument assignments, VST effect-slot assignments, render settings, album-art selection for MP3 renders, and user-visible metadata. Saved projects use a .mwproj file plus media folders beside it.

Track
-----
A track is one musical or audio lane. MIDI-style tracks contain notes and instrument assignments. AudioClip tracks reference imported or recorded audio media. Both MIDI tracks and AudioClip tracks can use the two-slot VST Effect chain during offline preview/export.

Sequence
--------
A sequence is an arrangement view or working region for a project. Sequence controls allow switching, creating blank sequences, and storing sequence thoughts/notes. Track and note edits can be scoped by the active sequence.

Staged media
------------
Staged media is audio that belongs to the current unsaved session but has not yet been committed to a saved project folder. Imported audio, applied recording takes, generated enhanced copies, rendered AudioClip arrangements, and MP3 album art can stage under workspace\temp\recordings\rec_... until Save Project commits them.

Editor-only Aux source
----------------------
An Aux source is an external audio file loaded only inside the AudioClip Editor to help build a mixed Main/Aux arrangement. It is not added as a project track and is not saved as its own project media. After an Aux trim is appended to the main arrangement, the arranged Aux block keeps its own source path and trim range for preview and Render To Track. Keep the original Aux file available until you render the arrangement.

Dry project AudioClip sources and wet monitoring
-------------------------------------------------
Imported AudioClip files remain dry. Normal AudioClip recording also writes the dry input signal to the project take. Track effects, track volume, master volume, and wet-monitor gain are not printed into the project source file. This keeps the take non-destructive so effects and levels can be changed later.

When Track Live Effects is enabled, the monitor path can pass the input through Effect Slot 1, then Effect Slot 2, track volume, and master volume before reaching the output device. The WAV writer still receives the dry pre-fader input. Record Test may create a disposable wet WAV for immediate audition, but that temporary file is not attached to the project.

Offline processing
------------------
Preview, Test Effect, selected-track render, selected-sequence render, AudioClip enhancement preview, AudioClip arrangement preview, and final export use offline render paths. Track Live Effects controls what you hear while recording; it does not change the dry project-capture contract. Final MP3 renders can embed selected album art; non-MP3 outputs leave album art unavailable.

========================
The main window is organized into project controls, project defaults, selected-track controls, preview/render controls, utility buttons, the track summary, and the log. The detailed button reference below is intentionally table-based so it remains useful even before final screenshots are captured.

Project Defaults controls

Selected-track controls
-----------------------
Control | Purpose | Commit behavior
--- | --- | ---

Instrument | Choose the selected track's instrument/preset/plugin. | Use Apply Track Settings to commit.
Open VST Instrument | Open the selected track's VST3 instrument editor. | Use Apply Changes in the editor after changing plugin parameters. The custom title bar shows track number, track name, Instrument, and plugin name.

VST Effect 1 Bypass | Temporarily skip slot 1 while keeping assignment/state. | Use Apply Track Settings after changing.

VST Effect 2 dropdown | Assign slot 2 of the selected track's VST Effect chain. | Slot 2 processes after slot 1.
VST Effect 2 Enable | Turn slot 2 processing on/off for preview/export. | Slot 2 can be used by itself or after slot 1.
VST Effect 2 Bypass | Temporarily skip slot 2 while keeping assignment/state. | Bypass is different from disabling because the slot remains configured.
Open Slot 2 | Open the editor for VST Effect Slot 2. | Available only after slot 2 has an assigned plugin and Enable is checked; the custom title bar uses fuller wording such as Track: #1 - Lead Vocal | S2 | Plugin: Compressor.
Track Volume | Adjust selected-track volume. | Use Apply Track Settings. AudioClip tracks use this value during preview/render/mix.
Master Volume | Adjust overall project output volume. | Preview/render uses the saved value for MIDI and AudioClip output.
Mute / Solo | Control selected-track participation in preview/render. | Use Apply Track Settings.

Preview and render controls
---------------------------
Control | What it does | Useful example
--- | --- | ---
Preview Project | Renders and plays a temporary full-project preview. | Check overall balance before export.
Render | Exports the full project using the chosen render settings. | Create a final WAV or compressed file.
Render Selected Track | Render only the selected track. | Check a vocal AudioClip effect chain by itself.
Render Selected Sequence | Render only the active selected sequence. | Export an alternate arrangement or section.
Export MIDI | Write MIDI data for external use. | Move note data into another sequencer.
Cancel Render | Request cancellation of a running render. | Stop a long render after noticing a wrong setting.
Preview Latest | Play the most recent rendered WAV where available. | Quickly audition the latest export.
Render Settings | Open options for stem retention and output cleanup. | Keep stems for mixing or delete temporary stem files automatically.

Rendered previews use one tail detector after the complete Effect Slot 1 -> Effect Slot 2 chain and final project mix. Preview output uses an approximately -80 dBFS threshold, 0.30 seconds of confirmed ending silence, 0.05 seconds of end padding, and one four-second maximum tail. Final render/export output uses an approximately -96 dBFS threshold, 1.0 second of confirmed ending silence, 0.15 seconds of padding, and one 12-second maximum tail. Both policies inspect the full tail window so delayed repeats after quiet gaps remain detectable.

Status, track summary, and log
------------------------------
The log is the authoritative place for detailed status: plugin scan results, unsupported plugin reasons, import results, staging paths, preview paths, render commands, VST effect-chain messages, warnings, and errors. The main window intentionally avoids large VST status text so the two effect-slot rows have room. The Window menu also acts as a window switcher: open VST instrument editors appear under VST Instrument, and open VST effect editors appear under VST Effect. VST instrument editor title bars use wording such as Track: #1 - Lead Piano | Instrument | Plugin: Dexed so the owning track is visible while editing.

4. Project Defaults And Track Settings
======================================

Project defaults
----------------
Project defaults are templates for future MIDI tracks. They decide what newly imported or newly created MIDI tracks should use by default. They do not automatically rewrite existing track assignments because that could destroy careful per-track choices.
Default area setting | Affects | Does not affect
--- | --- | ---
Backend | Future imported/new MIDI tracks | Existing tracks until changed directly
SoundFont/SF3 preset | Future tracks using the SF2 backend | AudioClip tracks
SFZ file | Future tracks using the SFZ backend | VST3 instrument/effect settings
VST3 instrument | Future tracks using VST3 Plugin backend | VST Effect chain slots
Render base name/format | Future render/export output | Track note data

Track settings
--------------
Track settings belong to the currently selected track. They include instrument assignment, track volume, mute/solo, AudioClip behavior where applicable, and both VST Effect slots. Apply Track Settings is the clear commit point for these controls.
WARNING: Do not rely on an open VST editor window to save track-level changes. The editor Apply Changes captures plugin parameters. Apply Track Settings captures dropdown, Enable, Bypass, and track controls.

Why there are separate Apply buttons
------------------------------------
Button | Scope | Why it exists
--- | --- | ---
Apply Project Defaults | Project template for future tracks | Prevents accidental changes to existing tracks.
Apply Track Settings | Selected track controls | Makes the selected track's assignment/effect/mixer state explicit.
VST editor Apply Changes | Plugin parameter state | Captures native plugin UI state into the track or slot.
Save Project | Project file and attached media | Commits metadata and staged AudioClip media to a saved folder.

6. Starting Projects From Files
===============================

Supported start points
----------------------
Source | Result | Typical next step
--- | --- | ---
MusicXML or MXL | Creates MIDI-style tracks and sequences from notation data. | Review instruments and use Apply Track Settings.
MIDI | Creates MIDI-style tracks from the file's note/channel data. | Choose a backend and match presets.
Audio file | Creates an AudioClip track pointing to staged or committed audio media. | Preview, add effect slots, and Save Project.
.mwproj | Reopens a saved Poor Man's Studio project. | Verify media paths and continue editing.

Unsaved-change prompts
----------------------
When starting a new project, opening another project, importing a file that replaces the current project, or exiting with unsaved changes, the app prompts you to save, discard, or cancel. Discard means the active unsaved project state and active staged AudioClip session are intentionally removed.
Choice | Meaning | Staged media behavior
--- | --- | ---
Save | Save the current project before continuing. | Attached staged AudioClip media is committed to the saved project.
Discard | Throw away current unsaved changes and continue. | Active staged AudioClip session is removed so it cannot attach to the wrong project.
Cancel | Do not continue the requested action. | Current project and staged session remain active.

7. Track Manager And Arrangement Workflows
==========================================
Track Manager is the organizational center for track names, sections, sequence relationships, and notes/thoughts. It complements the main-window selected-track controls and Piano Roll note editor.

Common track management tasks
-----------------------------
Task | Where to do it | Recommended workflow
--- | --- | ---
Rename tracks | Track Manager | Use descriptive names before opening VST editors so title bars show clear track context. Instrument editors and effect editors both include track context.
Create or change sequences | Sequence controls / Track Manager | Use Chg Seq to switch or create a blank sequence.
Document arrangement ideas | Sequence Thoughts | Keep notes in the project instead of relying on external scratch files.
Review track summaries | Main-window track summary | Check backend, library, VST instrument, effect slots, mute/solo, and volume.
Render a single track | Main render controls | Select the track, apply settings, then use Render Selected Track.

Naming advice
-------------
- Use musical names like Lead Vocal, Rhythm Guitar, Bass DI, Piano, or Strings Long instead of Track 1/2/3.
- Add role details when useful: Lead Vocal Comp, Drum Loop Imported, Room Verb Return, or Sketch Piano VST.
- Clear names are especially helpful because VST effect editor windows show the track number, slot, and plugin in the toolbar/title context.

8. Piano Roll Editing
=====================
The Piano Roll is the note editor for MIDI-style tracks. It is used for pitch, timing, velocity, note length, snap-grid, and beat-window work. AudioClip waveform editing is intentionally separate from MIDI note editing.

Piano Roll controls
-------------------
Control | Purpose | Example
--- | --- | ---
Open Piano Roll | Edit notes on the selected MIDI-style track. | Fix a bass note that starts late.
Beat Window | Choose how much time the Piano Roll shows at once. | Zoom to a four-beat phrase or broader section.
Page / window jump | Jump to a specific Piano Roll window number. | Move to bar/phrase areas without scrolling endlessly.
Key jump | Center a specific pitch name. | Jump to C4 or A5 while editing melody.
Snap grid | Constrain editing to a musical grid. | Edit sixteenth notes cleanly.
Preview region | Render the current region temporarily. | Audition a short phrase without exporting the whole project.

Recommended edit loop
---------------------
Select a track, open Piano Roll, make note edits, preview a small region, adjust track instrument/effects if needed, apply track settings, and then preview the full sequence or project. This keeps local note edits separate from track-level sound changes.

9. AudioClip Import And Editor Workflow
=======================================
AudioClip import lets you bring external audio into a project as a track. Imported audio can be used dry, processed through the two-slot VST Effect chain during preview/export, edited non-destructively in the AudioClip Editor, enhanced into a new full-source generated copy, arranged into repeated or overlapping local clips, combined with editor-only Aux source trims, or mixed with MIDI-rendered tracks.

Import behavior by project state
--------------------------------
Project state | Import destination | Project folder behavior
--- | --- | ---
Unsaved project | Current active staging session under workspace\temp\recordings\rec_...\input\audio\imported | No new workspace\projects folder should be created until Save Project.
Saved project | Project-relative input\audio\imported folder | Media belongs to the saved project folder.
Project discarded | Active staging session is removed | Imported media from that discarded unsaved project is intentionally deleted.

AudioClip import steps
----------------------
Step | Action | Result
--- | --- | ---
1 | Start or open a project. | The active project/session is known.
2 | Use Start From File or Import Audio to choose WAV, MP3, FLAC, or OGG. | The app creates or attaches an AudioClip track.
3 | For unsaved projects, verify the log reports staging under workspace\temp\recordings\rec_.... | This confirms the import is tied to the current session, not a random project folder.
4 | Optional: choose VST Effect 1 and/or 2, check Enable, adjust Bypass, and click Apply Track Settings. | The imported track's offline effect chain is committed.
5 | Preview, enhance, or render. | Temporary processed WAVs are created for previews; enhanced copies create new AudioClip media without overwriting the source.
6 | Save Project when you want to keep the imported clip. | Attached staged import moves to input\audio\imported.
WARNING: If you discard an unsaved project after importing audio, the staged imported audio is removed. This is the intended safety behavior so abandoned clips do not become orphans and do not attach to the wrong project later.

AudioClip Editor source trim
----------------------------
The AudioClip Editor opens from the main window, the Track Manager, or the View menu. The top waveform is the source trim area. Drag only the green Start handle or the red End handle to adjust the kept range, or type trim values directly. Click Apply Trim to commit the source trim metadata. The original imported or recorded media file is not overwritten.

Dirty-close behavior applies only to source trim changes. If the AudioClip Editor prompts on close, Apply Trim and Close commits pending source-trim metadata, Discard Pending and Close reverts only the pending source-trim edit, and Cancel keeps the editor open. This prompt does not delete or roll back any new arrangement track that was already created with Render To Track.

AudioClip Enhancement / Repair
------------------------------
The AudioClip Editor includes a source-level enhancement section for imported or recorded AudioClips that need cleanup or repair. Choose a Preset to select the enhancement style, such as mild cleanup, low-bitrate MP3 repair, warm smoothing, voice cleanup, mastering-lite, de-harshing, or loudness normalization. Choose Strength to control how aggressively the selected preset is applied. Strength is not a volume knob; it changes the processing intensity.

Preview Enhanced renders a temporary enhanced preview of the full AudioClip source and opens it in the Preview Player. This does not create a track, change project metadata, apply trim handles, or rewrite original media.

Create Enhanced Copy renders the full AudioClip source through the selected preset and Strength, then creates a new imported-style AudioClip track from the enhanced WAV. The original imported or recorded source remains untouched. If the project is already saved, the enhanced media is stored under input/audio/imported. If the project is unsaved, the enhanced media stages temporarily and migrates into input/audio/imported when Save Project or Save As completes.

This feature is enhancement and repair, not true restoration. A poor low-bitrate file can often be made less harsh, less thin, and more usable, but missing information from the original compression cannot be recreated.

AudioClip Editor local arrangement lane
---------------------------------------
The lower arrangement lane is a local sketch area for building a new AudioClip from frozen Main and Aux trims. Click Freeze Trim to lock the current Main kept range for placement. Then click in the arrangement lane to place the frozen Main clip. Click again in another position to place another copy of the same frozen Main clip. This repeat-click behavior is intentional and is the normal way to build loops or repeated phrases. Blank-lane clicks place the frozen Main trim; Aux trims are added intentionally from the Aux Source File window with Append to Main.

Append Clip places the frozen Main trim at the current audible end of the arrangement. Clip Start and Move Clip let you type an exact start time for the selected arranged clip. Placed clips are shown as transparent colored blocks so overlaps remain visible. Use the Clip # selector to choose an arranged clip. The selected clip is drawn on top and gets drag priority in overlap areas. Delete Clip removes the selected clip number. Extend +10s increases the available arrangement workspace. Horizontal movement is free-form rather than page-based. The arrangement workspace length is only editing space; it is not the final render length.


AudioClip Editor Aux source workflow
------------------------------------
Load Aux Source opens a normal audio-file picker for an editor-only secondary source. The Aux source is used only inside the currently open AudioClip Editor arrangement workflow; it is not added as a project track and is not saved as its own project media.

The Aux Source File window provides trim handles, Trim Start / Trim End fields, Preview Trim, Play Full Source, Freeze / Unfreeze, and Append to Main. It does not have its own arrangement lane. Freeze a range in the Aux window, then click Append to Main to add that frozen Aux trim to the end of the main arrangement. Closing the Aux window does not remove Aux clips already appended to the main arrangement.

Main arrangement clips are labeled with their source role, such as #1 Main, #2 Main, #3 Aux, and #4 Aux. Preview Arrangement and Render To Track mix Main and Aux clips together. Loading another Aux source later does not overwrite earlier Aux blocks; each appended Aux block keeps the source file path and trim range it had when it was appended. Only the final Render To Track result becomes a new project AudioClip track.

Preview Arrangement and Render To Track
---------------------------------------
Preview Arrangement renders a temporary preview of the current local arrangement. It lets you hear repeated, overlapping, Main, and Aux clips without creating a new track, changing the original source file, or committing new project media.

Render To Track renders the local Main/Aux arrangement into one new imported-style AudioClip track. The rendered file length follows the last audible placed clip, not the visible arrangement-window length. If the arrangement window extends to a later time but the last clip ends earlier, the exported arrangement stops at the last clip end to avoid trailing dead air. Track Volume and Master Volume are applied when AudioClip material is mixed during preview/render.

If the project is already saved, the new rendered arrangement media is written under the project input audio imported folder. If the project has not been saved yet, the new rendered arrangement is staged in the current temporary AudioClip session and is migrated into the saved project's input audio imported folder when Save Project or Save As completes. The original source media stays untouched and remains where it was.

10. AudioClip Recorder Workflow
===============================
The AudioClip Recorder records a dry project take into a project-session staging area, then lets you apply, redo, or discard it. Save / Apply attaches a stopped take to the current project in memory; Save Project commits attached takes into the saved project folder. Optional Track Live Effects provide wet monitoring without printing effects or fader levels into the project source file.

Recorder buttons and settings
-----------------------------
Control | Purpose | Notes
--- | --- | ---
Record | Start a take into the active session staging folder. | Do not close the app mid-take if you need the file.
Stop | Stop the active take. | After stopping, choose Save / Apply, Redo, or Discard.
Save / Apply | Attach the stopped take to the current project in memory. | Does not force Save Project; the take remains staged until the project is saved.
Redo From Top | Abandon the stopped take and start over. | Keeps unwanted takes out of the project.
Discard Take | Delete or abandon the current stopped take. | Use when you know the take is not needed.
Format | Choose WAV/FLAC/MP3/OGG media format. | WAV/FLAC are lossless; MP3/OGG use the quality setting.
Quality | Choose bitrate for compressed formats. | Ignored for lossless formats.
Mic Gain | Adjust input gain before recording. | Avoid clipping before recording.
Track Live Effects | Optional two-slot monitor path. | Controls whether you hear Slot 1 then Slot 2 while recording; the project take remains dry.
Record Test | Record a short temporary test and play it back. | The test file is deleted automatically.

Dry recording and wet-monitor behavior
--------------------------------------
State | Result | Best practice
--- | --- | ---
Normal project recording | The WAV writer receives dry pre-fader input. | Keep the original take flexible for later editing and mixing.
Track Live Effects checked with a valid chain | You hear Input -> Slot 1 -> Slot 2 -> Track Volume -> Master Volume. | Use for performance monitoring while preserving a dry take.
A required monitor effect fails | The complete wet monitor chain stops, but dry recording continues. | Check the log and effect compatibility before another take.
Track Live Effects unchecked | No wet monitor chain is added. | Use hardware direct monitoring or normal dry monitoring as appropriate.
Record Test | A disposable wet test WAV may be created for audition. | It is temporary and is not attached to the project.

The two slots are treated as one intended monitor chain. Poor Man's Studio does not silently continue with only part of the requested chain when a required stage fails.

Recording commit model
----------------------
Moment | File location | Project state
--- | --- | ---
During recording | workspace\temp\recordings\rec_... | Not yet attached as a project clip.
After Stop | Still in staging | User chooses Save / Apply, Redo, or Discard.
After Save / Apply | Still in staging | Attached to the current project in memory.
After Save Project | input\audio\recorded | Committed to the saved project folder.
After Discard project | Staging session removed | Applied staged takes from that unsaved project are removed.

11. Two-slot VST Effect Chain
=============================
The Two-slot VST Effect chain gives each track two ordered insert slots. It works for MIDI/instrument tracks and for imported or recorded AudioClip tracks. The main-window layout stays consistent: each slot row begins with the assignment dropdown, followed by Enable, Bypass, and Open.
VST Effect 1: [dropdown] [Enable] [Bypass] [Open Slot 1]
VST Effect 2: [dropdown] [Enable] [Bypass] [Open Slot 2]

Processing order
----------------
source track
  -> VST Effect 1, when assigned + enabled + not bypassed
  -> VST Effect 2, when assigned + enabled + not bypassed
  -> preview/export output

Slot rules
----------
Rule | Behavior | Reason
--- | --- | ---
Dropdown assignment | Chooses the Supported Effect for that slot. | Assignment must be independent from processing on/off.
Enable | Allows the slot to process during preview/export and allows its editor to open. | A slot can be assigned while disabled, but Open Slot stays unavailable until Enable is checked.
Bypass | Skips processing but preserves assignment and plugin state. | Useful for A/B testing.
Open Slot | Opens the editor for that track and slot. | Only enabled when the slot has an assigned plugin and its Enable checkbox is checked; the toolbar/title context identifies track number, slot shorthand, and plugin.
Apply Track Settings | Commits dropdown, Enable, and Bypass. | Track-level state is explicit and saved.
Apply Changes | Captures plugin parameter state from the open editor. | Plugin UI state is separate from track-level enable/assignment.
Default | Recreates the same VST3 or CLAP plugin as a new instance and immediately applies that default state. | Preserves the track/slot assignment, Enable/Bypass, chain order, and saved Snapshots; confirmation warns that current unapplied and applied state will be discarded.

Using the same plugin in both slots
-----------------------------------
The same VST3 effect can be assigned to slot 1 and slot 2. This is allowed and useful for staged processing such as light compression followed by limiting, or two different delay/reverb settings. Each slot owns its own saved plugin state, Enable flag, and Bypass flag. During preview/export, slot 1 renders first and slot 2 processes the result.
NOTE: When the same plugin is open in both slots, use the editor toolbar/title context to verify the target. The compact toolbar uses wording like Track #1 - S1 - Reverb. The custom title bar can show fuller wording like Track: #1 - Lead Vocal | S2 | Plugin: Compressor.

Effect editor toolbar
---------------------
Toolbar item | Purpose | Important detail
--- | --- | ---
Compact context label | Shows the target as Track #1 - S1 - Reverb. | Useful when multiple tracks or duplicate plugins are open.
Apply Changes | Captures the current plugin state into the owning track slot. | Required after editing plugin parameters.
Default | Reset the owning VST3 or CLAP effect to the state of a new instance. | The same slot assignment, Enable/Bypass state, chain order, and saved Snapshots remain; the editor is recreated after confirmation.
Test Effect | Processes the bundled short WAV through this slot. | Uses the editor's owning slot, not a different track.
Snapshot Slot 1-5 | Choose a host-side snapshot slot. | Snapshots are stored outside the project under workspace\vst3\snapshots.
Load | Load a snapshot into the current editor and apply it. | Check the compact toolbar/title context first.
Save | Save the current plugin state to the selected snapshot. | Useful for reusable favorite settings.
Clear Current | Clear the selected snapshot slot. | Asks for confirmation.
Clear All | Clear all five snapshot slots for that plugin/role. | Asks for confirmation.

Plugin Editor Default Button
----------------------------
Every VST3 and CLAP instrument/effect editor toolbar includes Default beside Apply Changes. Default resets the owning plugin to the state of a newly created instance without removing the track or effect assignment.

After confirmation, Poor Man's Studio:
- stops active playback before changing project plugin state;
- clears only the owning instrument/effect state;
- preserves plugin identity, backend, track, effect slot, chain order, Enable, and Bypass;
- preserves all Snapshot files;
- closes the old editor safely and reopens the same owner as a fresh plugin instance;
- marks the project dirty so the reset can be saved normally.

The confirmation warns that current unapplied editor changes and the applied project state will be discarded. Cancel makes no change. Default does not delete Snapshots or automatically save the project.

Recommended test:
1. Change a plugin parameter and click Apply Changes.
2. Save a Snapshot.
3. Click Default and confirm.
4. Verify the same track/slot and plugin reopen at new-instance settings.
5. Verify the Snapshot still loads and Enable/Bypass/slot order are unchanged.
6. Save and reopen the project to confirm the reset state persists.

For two effect slots using the same plugin, reset each slot separately and use the toolbar/title context to confirm which owner is being changed. The reset reopens the editor by its owning track and slot, not by whichever track is currently selected in the main window.

Effect chain troubleshooting checklist
--------------------------------------
- Confirm the desired slot has a Supported Effect selected in the dropdown.
- Confirm Enable is checked for that slot.
- Confirm Bypass is unchecked for that slot.
- Click Apply Track Settings after changing dropdown, Enable, or Bypass.
- Open the correct slot editor and click Apply Changes after changing plugin parameters.
- Use Default only when you intend to discard the current applied state and reopen that same effect assignment at its new-instance settings; snapshots are not deleted.
- Check the log for missing bundle, unsupported plugin, processing, or render errors.

===============================

Live MIDI Monitoring and Recording
----------------------------------
Open Project > MIDI Input / Live Monitor or Window > MIDI Input / Live Monitor to play a VST3 or CLAP instrument from a physical MIDI keyboard or pad and to record controller performances into editable MIDI-track notes.

Control | Purpose | Notes
--- | --- | ---
MIDI Input Device | Selects one physical MIDI input exposed by JUCE. | Use Refresh Devices after connecting or disconnecting hardware.
MIDI Channel | Chooses Omni or one channel from 1 through 16. | Omni accepts Note On/Off events from every MIDI channel; a numbered channel filters other channels before monitoring or recording.
Refresh Devices | Rescans the available physical MIDI input devices. | Locked during Count-In, playback preparation, and active recording so the selected route cannot change mid-take.
Count-In | Chooses Off, 1 Bar, or 2 Bars before MIDI recording begins. | The choice is saved as an application preference. Count-in clicks follow the current project tempo/time signature, accent beat 1, and finish before backing playback/capture owns the audio output.
Metronome | Chooses Off or On for continuous clicks while MIDI capture is active. | The choice is saved as an application preference. Click phase follows the absolute project beat/bar grid. During punch pre-roll, the continuous metronome remains silent until Punch In.
Quantize | Chooses Off, 1/4, 1/8, 1/16, 1/32, or 1/64 post-take start-position quantization. | The choice is saved as an application preference. Quantization affects only newly recorded Note On/start ticks; normal non-punch takes preserve duration and other note fields.
Punch | Chooses Off or On for runtime MIDI punch recording. | Punch points are temporary for the current project session and are not written to the project file. Use Set In / Set Out at the current project position; Clear removes the region and turns both Punch and Loop Record Off.
Loop Record | Chooses Off or On for repeated MIDI overdub passes inside the same runtime In/Out region. | Count-In runs once before the first pass. Each Out closes the current pass and wraps backing to In until Stop Recording is pressed.
Loop Takes | Chooses Merge or Review for the result of a Loop Record session. | Merge preserves the established whole-session overdub commit. Review retains each completed/current pass separately after Stop Recording for whole-pass review or segment comping. In project format 15, the target MIDI track can save one named Active review plus named Archived review snapshots containing retained passes, comp state, retained CC64 sustain metadata, Cross-Pass Notes mode, and organizational Tags/Notes. Format-9/10/11/12/13/14 projects remain load-compatible; format-14 and older reviews default Cross-Pass Notes to Off when the field is absent, format-13 reviews migrate with empty Tags/Notes, and older reviews still default Boundary Notes to Cut and Sustain Pedal to Ignore.
Boundary Notes | Chooses Cut or Preserve Same Pass while TAKE REVIEW is in Comp mode. | Cut clips at every segment end. Preserve Same Pass can carry a real note, including an Apply-CC64 pedal-held note, through adjacent segments using the same retained pass, but still stops at a pass change or Loop Out and never invents a Note On. Hover helper bubbles on Review/Comp controls explain destructive versus non-destructive actions.
Cross-Pass Notes | Chooses Off or Bridge Exact while TAKE REVIEW is in Comp mode. | Off preserves the established pass-change behavior. Bridge Exact is conservative and only acts when Boundary Notes = Preserve Same Pass: at a selected-pass change, exactly one live left note must reach the boundary and exactly one same-pitch/same-channel real Note On from the next selected pass must begin exactly on that boundary. Gaps, near matches, pitch/channel mismatches, and ambiguous multiple matches are never bridged. The earlier note keeps its velocity/articulation; no synthetic Note On is created.
Sustain Pedal | Chooses Ignore or Apply CC64 while TAKE REVIEW is active. | Ignore preserves retained Note On/Off durations. Apply CC64 interprets controller 64 per MIDI channel (0-63 Up, 64-127 Down): a note released while the pedal is Down may continue until the next pedal-up event, a Cut/pass-change boundary, or Loop Out. Pedal changes do not resurrect notes whose real Note Off already occurred; same-tick CC64 events use recorded order with the last state winning.
Take Review Manager | Project > Take Review Manager opens named Active and Archived MIDI review management. | The main window still shows Pending Takes: N for Active unresolved reviews only. Resume opens Active review; Archive moves it to archive and frees the Active slot; Snapshot Active creates an independent Archived checkpoint while leaving Active unresolved; Restore returns one archive to the Active slot; Duplicate Archive copies an Archived review on the same track; Copy to Track copies an archive to another MIDI track with a fresh review ID; Move to Track transfers an archive to another MIDI track while preserving its review ID; Rename changes only the saved name; Delete Archive removes only the selected archive.
Review Mode | Chooses Whole Pass or Comp while TAKE REVIEW is active. | Whole Pass keeps Audition Pass / Keep Selected / Keep All. Comp enables Beat/Bar/Custom segment selection, per-segment pass assignment, Audition Comp, and Keep Comp.
Comp Grid | Chooses Beat, Bar, or Custom while Review Mode = Comp. | Beat/Bar follow the absolute project grid. Custom starts as one In-to-Out segment and accepts user-positioned internal boundaries. Changing grid rebuilds the map and resets segments to the currently selected whole pass.
Custom Split | Adds/removes internal Custom boundaries. | Position the Piano Roll Preview Player strictly inside In/Out, then Add Boundary. Select an existing internal boundary and Remove Boundary to merge its adjacent segments; the merged segment keeps the pass assignment from the left side. In/Out stay locked.
Apply / Save | Opens the selected device, applies the channel filter, and persists the accepted selection. | Locked during Count-In, playback preparation, and active MIDI recording so the route cannot change underneath a take.
Start Monitor | Routes Note On/Off and velocity to the currently selected VST3 or CLAP instrument track. | The track must have a valid assigned instrument plugin. Locked while the MIDI recording workflow is busy.
Panic | Releases currently active controller notes. | Remains available during Count-In, preparation, and recording. During recording, held recorded notes are finalized at the Panic position and recording continues; during Count-In, Panic cancels pre-roll.
Stop Monitor | Releases active notes and stops ordinary live instrument monitoring. | Available for normal live monitoring but locked during Count-In, playback preparation, and active recording; use Stop Recording for the take.
Arm Selected | Fixes the current MIDI track as the recording target by stable track identity. | AudioClip tracks cannot be armed. Apply or discard pending Piano Roll edits before arming. The target is locked while the recording workflow is busy.
Record MIDI | Starts optional count-in, then project playback and transport-synchronized MIDI capture for the armed track. | With Punch/Loop Off, behavior is unchanged. With Punch On, playback may run before Punch In while capture is gated and Punch Out ends the take automatically. With Loop Record On, the same In/Out region repeats overdub passes until Stop Recording. If no MIDI input is open, Loop Record may still run an empty-pass backing-wrap diagnostic so audible Out->In continuity can be checked without a controller; zero-note diagnostic sessions do not change project data or Undo history. An invalid region or a start at/after Out blocks Record MIDI.
Stop Recording | Closes held notes and ends the active recording workflow. | With Loop Takes = Merge, the full loop session commits as one Undo Take unit. With Loop Takes = Review and captured notes present, Stop Recording enters TAKE REVIEW without changing project notes; resolve it with whole-pass Keep actions, Keep Comp, or Discard.
Undo Take / Redo Take | Reverts or reapplies complete MIDI recording takes. | Up to 10 recording undo states are kept for the current session. They are locked during Count-In, preparation, and recording and also blocked while the target Piano Roll has unapplied edits.
Close | Closes the MIDI Input / Live Monitor window. | Locked during Count-In, playback preparation, active recording, and TAKE REVIEW. Resolve TAKE REVIEW with Keep Selected, Keep All, Keep Comp, or Discard before closing.

Take Review management is project-level rather than hardware-dependent. Project > Take Review Manager shows every named Active and Archived MIDI review in project/track order. Each MIDI track may have zero or one Active review and zero or more Archived snapshots. Resume reselects the Active review by stable track and review-session identity, reconstructs its saved TAKE REVIEW state, and opens the existing MIDI review UI without dirtying the project merely by resuming. Archive moves an Active review into inert project archive storage without committing MIDI notes and frees the track for another Review recording. Snapshot Active deep-copies the saved Active review into a new inert same-track Archived checkpoint while keeping the original Active review/session ID unresolved and leaving Pending Takes unchanged; automatic names use `Name Snapshot`, then `Name Snapshot 2`, and so on with case-insensitive collision skipping. Restore moves one Archived review back into the Active slot and is rejected while that track already has an Active review. Duplicate Archive deep-copies only the selected Archived review onto the same track, assigns a new stable review-session ID, appends the copy to that track's archive list, and chooses `Name Copy`, then `Name Copy 2`, and so on. Snapshot/duplicate copies retain the source musical/review payload, Tags, and Notes but are independent afterward; they do not change project MIDI notes. Rename changes only the review name. Discard Active and Delete Archive each confirm and affect only their selected review. Removed/stale tracks or review-session IDs are rejected rather than falling through to another row. The Window menu can bring the manager forward while it is open. Helper bubbles describe Pending Takes, Review selection, Resume, Archive, Snapshot Active, Restore, Duplicate Archive, Rename, Discard Active, Delete Archive, and Refresh.

The recording status area explicitly shows IDLE, ARMED, COUNT-IN, PREPARING PLAYBACK, PUNCH PRE-ROLL, RECORDING, LOOP RECORDING - PASS N, or TAKE REVIEW, together with the stable armed target and active Count-In, Quantize, Metronome, Punch, Loop Record, and Loop Takes choices. During recording busy states, device/channel routing, Refresh Devices, Apply / Save, Start Monitor, Stop Monitor, Arm Selected, Count-In, Quantize, Metronome, Punch/Loop editing, Undo Take, Redo Take, and Close are locked while Panic and Stop Recording remain available. During TAKE REVIEW, normal route/record/project-changing controls remain locked. Whole Pass exposes the pass selector plus Audition Pass, Keep Selected, Keep All, and Discard. Comp exposes Beat/Bar/Custom grid selection, a segment selector, per-segment pass assignment, Custom boundary editing when selected, Audition Comp, Keep Comp, and Discard.

Recording stores pitch, velocity, original MIDI channel, project start tick, and duration. Note On and Note Off are paired without collapsing overlapping notes of the same pitch. MIDI timing follows the same project transport that drives backing playback. If Stop Recording, Panic, device disconnect, or another playback/project transition occurs while notes are held, the recording code closes those held notes at the corresponding transport position so they do not become hanging zero-duration events.

The recording target is the armed stable track, not whichever track becomes selected afterward. Changing the main selected track while a take is in progress therefore does not steal the live route or redirect recorded Note Off events. When not recording, changing the selected track during ordinary live monitoring still releases the old target before attempting to route to the new selected VST3 or CLAP instrument track.

Recorded notes are appended to existing project notes rather than replacing earlier material. Record MIDI optionally plays a 1-bar or 2-bar audible count-in, then starts Preview Project backing playback and keeps timing on the existing project transport. Count-in remains pre-roll only and never shifts project time. The armed stable track remains the recording owner even if the main selected track changes during the take.

With Punch and Loop Record Off, capture starts with project playback exactly as before. Punch and Loop Record share the same temporary Set In / Set Out project-tick boundaries for the current project session. With Punch On, the region retains the established automatic punch behavior. If playback starts before Punch In, backing playback runs in PUNCH PRE-ROLL while incoming notes remain monitoring-only; capture begins at Punch In. Starting inside the region captures immediately. Starting at or beyond Punch Out is rejected. Notes whose Note On occurs before Punch In are not recorded, even if held across Punch In. Notes beginning at or after Punch Out are ignored. Held recorded notes are finalized at the exact Punch Out tick, and the punch take ends automatically. The backing-stop path now follows the same logical Punch Out position: rendered fallback reads the Windows MCI player's current position directly near the boundary, the final boundary is polled in a short guarded window, and only one automatic stop claim is accepted for the active punch generation. Existing notes are never erased; punch recording remains overdub-style. Punch points are runtime-only and are not serialized into the project file.

If Quantize is enabled, only the just-completed take is processed after capture stops and before append. In a punch take, the resulting notes are constrained back inside the Punch In/Out region so quantization cannot move a note outside the punch boundaries. Undo Take restores the complete pre-take state and Redo Take restores the committed take. When Metronome is On, continuous clicks run only while actual MIDI capture is active; during punch pre-roll they stay silent, then begin on the absolute project grid at Punch In. Panic during punch pre-roll sends monitoring All Notes Off without creating recorded notes; Panic during capture finalizes held recorded notes while the punch workflow continues. Stop Recording can manually end the punch workflow early. Count-in, metronome, punch clicks, and monitoring remain absent from saved MIDI, AudioClip media, normal render output, and exports. The stopped preview position remains at Punch Out so the user-visible logical transport position matches the exact MIDI boundary. This tighter coordination is not a claim of sample-accurate audio stopping; real driver/plugin/backend timing remains a native acceptance item. With Loop Record On, the same In/Out region repeats MIDI overdub passes. Starting before In uses the established punch pre-roll and activates pass 1 at In; starting inside the region begins a partial pass 1 immediately. At each Out, held recorded notes are closed at the exact Out tick, the pass is quantized/constrained, and backing wraps to In for the next pass. A key held across the wrap does not manufacture a new Note On in the fresh pass; it must be released/retriggered. Count-In occurs only before the first pass, metronome phase remains tied to the absolute project grid, Panic finalizes current held notes without ending the loop workflow, and Stop Recording ends the loop workflow. With Loop Takes = Merge, Stop Recording commits all completed/current-pass notes as one Undo Take / Redo Take unit exactly as before. With Loop Takes = Review, every completed/current pass retains a pass number and its already-quantized/constrained note vector. Stop Recording enters TAKE REVIEW without mutating project notes. In project format 14, that unresolved review becomes the named Active review on the target MIDI track: retained passes, the loop In/Out ticks, selected pass, review mode, comp grid, custom boundaries, and segment/pass assignments survive Save Project and reopen. The pass selector chooses one whole pass; Audition Pass renders a non-destructive project snapshot containing the selected pass, Keep Selected appends only that pass, Keep All appends every retained pass and is equivalent to Merge, and Discard removes the persisted review without adding project notes or creating take-history. A Keep action creates one Undo Take unit that snapshots both the pre-Keep notes and pending review state; Undo can restore the unresolved TAKE REVIEW session and Redo can restore the committed result. Review state is guarded by stable project/track identity; another recording into a track with an unresolved Active review is rejected until that review is Kept, Discarded, or Archived. TAKE REVIEW also supports runtime segment comping. Beat/Bar segments are clipped to the loop In/Out region; Custom starts as one locked In-to-Out segment and accepts internal boundaries at the current Preview Player position. Adding a boundary splits one segment and inherits its pass on both sides; removing a selected internal boundary merges adjacent segments and keeps the left-side pass. Each segment selects one retained pass. Note ownership always follows the real Note On in [segment start, segment end), so a note that began before a segment is never manufactured at its boundary. Boundary Notes = Cut clips a selected note exactly at each segment end. Boundary Notes = Preserve Same Pass allows that real note to continue through consecutive adjacent segments assigned to the same retained pass, while still clipping at the first pass-change boundary or Loop Out; notes from different passes are never fused merely because pitch/channel match. Audition Comp is non-destructive and Keep Comp appends the generated comp as one Undo Take / Redo Take unit. Comp edits such as pass selection, Review Mode, grid changes, segment assignments, Custom boundary edits, and Boundary Notes mode are persisted project state and therefore mark the project dirty; audition alone does not. An all-empty Keep/Discard can remove persisted review state without adding notes or take-history. Sustain Pedal = Ignore preserves the retained Note On/Off result. Sustain Pedal = Apply CC64 uses channel-specific retained CC64 data for whole-pass audition/Keep and comp audition/Keep; CC64 value 64 is Down, 63 is Up, pedal state may carry into the next retained loop pass, Panic forces retained sustain state Up, and Loop Out remains the hard maximum. Controller events are not written as general project automation; their musical effect is baked into kept NoteEvent durations. Loop Takes = Merge remains unchanged. Loop recording remains overdub-only; the named Active review and Archived review snapshots preserve retained passes, comp maps, Boundary Notes mode, Sustain Pedal mode, pass-start sustain state, CC64 events, and organizational Tags/Notes in project format 14. Audible wrap timing follows the hardened playback/seek transaction architecture and is not claimed to be sample-accurate. There is no destructive replacement, saved loop markers, AudioClip loop recording, multiple loop regions, or simultaneous multi-track MIDI recording in this workflow.

If the selected MIDI device disconnects, Poor Man's Studio stops live monitoring and finalizes an active MIDI take before clearing the live route. Reconnect the device, click Refresh Devices, and apply the selection again. Enabled same-backend effect slots remain in their normal Slot 1 -> Slot 2 order. A live MIDI request with an enabled cross-backend effect chain is refused rather than silently bypassing part of the intended chain.

CLAP Settings / Compatibility includes Plugin Graphics Adapter, Refresh Adapter List, Max Open CLAP Windows, Safe CLAP Plugin UI Mode, and compatibility/details text for detected graphics adapters. Max Open CLAP Windows counts only CLAP instrument and effect editors and accepts values from 1 through 16.


Helper bubbles
--------------

24. Glossary
============
Term | Meaning
--- | ---
AudioClip | A track/media reference for imported or recorded audio.
Bypass | Skip a configured effect while preserving assignment and state.
Dry | Source audio without printed effects.
Effect chain | Ordered slot processing: slot 1 then slot 2.
Offline preview/export | Temporary or final render path where effects are processed.
Project defaults | Template settings for future imported/new MIDI tracks.
Snapshot | Host-side saved plugin state slot for reuse.
Staged media | Unsaved-session audio media not yet committed to a saved project folder.
Supported Effect | A VST3 plugin classified for use in VST Effect dropdowns.
Supported Instrument | A VST3 plugin classified for use as a MIDI track instrument.
Track settings | Selected-track instrument, mixer, and VST effect-slot controls.

Loop-wrap continuity diagnostics. Each Out->In transition is one generation/pass-scoped wrap transaction. The log reports the backend, Out-boundary lateness, pass-finalization time, seek/restart command time, total wrap-command time, and next-pass Playing/capture acknowledgement when it becomes available. Duplicate, stale, wrong-pass, and cancelled wrap stages are rejected. With Loop Record On and a valid region, an armed MIDI track can run this backing-wrap diagnostic even when no MIDI input device is open; the passes stay empty and stopping the session leaves project notes and Undo history unchanged. The logical MIDI boundary remains exact Out and the logical restart remains exact In. This diagnostic does not claim sample-accurate or gapless audio; it makes native behavior measurable and easier to listen to.

Loop-take review. Loop Takes = Merge / Review. Review mode preserves per-pass identity after loop capture, keeps project notes untouched until resolution, supports non-destructive whole-pass audition, Keep Selected, Keep All, and Discard, and creates one take-history step only when material is actually kept. In current format-15 projects, each MIDI track can keep one named Active review plus named Archived review snapshots. The Active review resumes after reopen and includes retained CC64 sustain metadata, Sustain Pedal mode, and Cross-Pass Notes mode. Format-9/10/11/12/13/14 project data remains compatible; missing Cross-Pass Notes defaults to Off, missing Boundary Notes defaults to Cut, and missing Sustain Pedal defaults to Ignore. Merge remains the legacy-compatible default and is not changed by Apply CC64.

Loop segment comping. During TAKE REVIEW, Review Mode = Comp builds a comp map over the existing In/Out region. Comp Grid = Beat or Bar creates project-grid-aligned segments whose first/last segments clip to the loop region. Comp Grid = Custom starts with one In-to-Out segment; position the Preview Player strictly inside the region and choose Add Boundary to split it. Splitting preserves the selected pass on both new sides. Select an internal Custom boundary and Remove Boundary to merge adjacent segments; the merged segment keeps the left-side pass assignment. In/Out cannot be removed. Select any segment and assign one retained pass. Boundary Notes = Cut preserves the original rule: a selected note is clipped at that segment end. Boundary Notes = Preserve Same Pass lets a real note continue through adjacent segments assigned to the same retained pass. Cross-Pass Notes = Off preserves the established rule that a pass-change boundary stops that continuation. Cross-Pass Notes = Bridge Exact is an opt-in conservative exception: only when Preserve Same Pass is active, exactly one live note from the left selected pass and exactly one same-pitch/same-channel real Note On from the next selected pass must meet exactly at the pass-change boundary. The left note is extended through the right note, the matching right boundary Note On is suppressed, and the earlier note keeps its velocity and articulation. Apply CC64 may make the left note effectively live at the boundary, but pedal state is still evaluated independently within each retained pass and is never fused across passes. Any gap, near match, pitch/channel mismatch, or multiple matching candidates leaves the existing clipped notes untouched. No synthetic Note On is created. Audition Comp is non-destructive; Keep Comp appends the generated comp as one Undo Take / Redo Take unit. Whole-pass Review remains available. Project format 15 persists the named Active review, Archived review snapshots, stable review-session IDs, comp maps, Boundary Notes mode, Cross-Pass Notes mode, Sustain Pedal mode, pass-start pedal state, retained CC64 events, Tags, and Notes; format-9/10/11/12/13/14 projects still load normally, with missing/unknown Cross-Pass Notes defaulting to Off, missing/unknown Boundary Notes defaulting to Cut, and missing/unknown Sustain Pedal mode defaulting to Ignore. Review/comp edits that change persisted state mark the project dirty; audition alone does not.

Take Review Manager. Project > Take Review Manager opens all named MIDI Take Reviews in project/track order. Each MIDI track can have zero or one Active review and zero or more Archived reviews. Pending Takes on the main window counts Active unresolved reviews only. Resume opens an Active review without changing project notes. Archive moves the Active review into project archive storage and frees the track for another Review recording without committing notes. Snapshot Active makes an independent same-track Archived checkpoint while leaving the Active editor unresolved. Duplicate Archive makes another independent Archived copy on the same MIDI track. Copy to Track creates an independent Archived copy on a different MIDI track in the same project; the destination receives a fresh review-session ID and deterministic Copy / Copy 2 naming, while the source review, destination Active review, Pending Takes count, and project MIDI notes remain unchanged. Move to Track transfers the selected Archived review to a different MIDI track in the same project while preserving the review-session ID. The destination archive is created before source removal, source deletion occurs only after destination validation/creation succeeds, and a case-insensitive destination name collision uses deterministic Move / Move 2 naming. AudioClip tracks and the source track are excluded from both cross-track destination choosers. Copy and Move are allowed even when the destination has an Active review because the incoming review remains Archived; Restore remains rejected until that Active review is resolved. Rename changes only the saved review name. Delete Archive permanently removes only the selected archive after confirmation. Archived reviews are inert: restore them before auditioning, editing, keeping, or discarding. Track ownership uses stable track IDs and each review uses a stable review-session ID, so rename/reorder/refresh cannot silently retarget a review.

25. Simulation And Regression Tests
===================================
Simulation / Regression is a deterministic diagnostic mode for testing important audio, MIDI, persistence, recovery, transport, tail-policy, and final-mix content-ending contracts without opening physical audio devices, MIDI devices, or third-party VST3/CLAP plugins. It is a regression aid, not a replacement for native Windows/JUCE hardware and plugin acceptance testing.

How to run it
-------------
Method | Workflow
--- | ---
Main application | Choose Help > Run Simulation / Regression Tests. The suite runs without changing the current project or opening hardware/plugin devices.
Standalone runner | Build and run workspace\simulation\PoorMansStudioSim.exe. With no arguments it runs every scenario.
List scenarios | Run PoorMansStudioSim.exe --list.
Selected scenarios | Run PoorMansStudioSim.exe --scenario F02 --scenario H01.
Choose result folder | Add --output followed by a folder path.
JUnit output | Add --junit to also write last_results.junit.xml for automated build/regression tooling.
Timing diagnostics | Add --timing to also write last_timing.txt with per-scenario elapsed times. Timings are informational only and are not pass/fail thresholds.
Project fixture seed | Add --seed VALUE to choose the randomized H02 ProjectSerializer fixture set. VALUE may be decimal or 0x-prefixed hexadecimal. The default remains 0x06770077.

Results and deterministic artifacts
-----------------------------------
The runner writes last_results.txt for a human-readable summary and last_results.json for machine-readable pass/fail data. The in-app command writes both files under workspace\simulation. Standalone --junit additionally writes last_results.junit.xml, and --timing writes last_timing.txt. Timing values vary by machine and are diagnostic only.

Every run also writes deterministic PCM16 WAV fixtures under workspace\simulation\artifacts (or under the chosen --output folder): dry_capture_fixture.wav, wet_monitor_fixture.wav, and artifact_manifest.txt. The manifest records the fixed sample rate, sample count, byte size, and FNV-1a hash so files can be compared across builds.

A process exit code of 0 means all selected standalone scenarios passed and requested files were written, 1 means one or more scenarios failed, and 2 means the command line or an output operation was invalid.

MIDI CONTROLLER LANE — GRAPHICAL POINT EDITING (v0.67.36)
----------------------------------------------------------
The MIDI Controller Lane now includes a graphical canvas above the event list. The canvas displays the selected track/channel/controller as discrete MIDI CC state: each point changes the value at its exact project tick, and the held state is drawn as a staircase until the next event. This is not interpolated automation.

Click a graphical point to select the same stable controller event shown in the list. Drag one point horizontally to change tick and vertically to change value. Mouse-up commits one controller-edit transaction, so one drag is one Undo CC step. Escape cancels an active drag. Empty-canvas selection, scrolling, zooming, changing Snap, and other view operations do not dirty the project.

Snap applies only to horizontal drag timing. Off preserves the exact integer project tick under the mouse. 1/4, 1/8, 1/16, 1/32, and 1/64 snap to the nearest grid based on the project PPQ; exact half-grid ties go forward. Value remains an integer 0-127 and is never quantized by Snap. Existing points are not moved merely because Snap is changed.

If a dragged point lands on an existing point at the same track + channel + controller + tick, the existing deterministic lane collision rule remains in force: one effective point remains, the dragged event keeps its stable ID, and Undo CC restores the displaced event and both original identities.

Project CC64 remains ordinary sustain playback data and does not rewrite NoteEvent duration. TAKE REVIEW Sustain Pedal = Apply CC64 remains a separate retained-pass comp-duration interpretation. Project format remains 16.

Not included in v0.67.36: freehand painting, double-click point creation, multi-select/box selection, interpolation/ramps/smoothing, MIDI Learn, incoming CC recording, or MIDI-file CC import/export round trip.

STANDARD MIDI FILE CONTROLLER IMPORT (v0.67.37)
------------------------------------------------
Standard MIDI File import now retains arbitrary Control Change messages (CC 0-127) as ordinary project MIDI Controller Lane events. Imported controller points preserve the MIDI file's channel and value and use the same source-tick-to-project-tick scaling already used by note import. No MIDI input device is required.

A MIDI-file track is now retained when it contains notes OR controller events, so controller-only automation tracks are no longer discarded. Metadata-only tracks still do not manufacture project instrument tracks. Multiple controller messages for the same track + channel + controller + tick resolve deterministically with the last source value winning, matching the project's one-effective-event-per-lane/tick contract. Different channels or controllers may coexist at the same tick.

CC0 Bank Select MSB and CC32 Bank Select LSB continue to participate in the established imported instrument/bank assignment and are also retained as editable project controller-lane events. Existing Program Change/instrument matching behavior is otherwise unchanged.

Imported CC64 is ordinary project Sustain data used during playback/render. It does not rewrite NoteEvent duration and does not create or modify TAKE REVIEW Sustain Pedal = Apply CC64 metadata. The two CC64 systems remain separate.

Controller import understands MIDI running status and rejects incomplete/truncated controller messages without fabricating project controller events. Imported controller points receive stable project event IDs and survive normal project-format-16 save/reopen. Project format remains 16.

Not included in v0.67.37: user-facing MIDI controller export/round-trip policy changes, live incoming CC recording, MIDI Learn, Program Change lanes, pitch bend/aftertouch lanes, 14-bit CC/NRPN/RPN, interpolation, or Take Review controller commit.



MIDI CONTROLLER EXPORT AND CLEAN ROUND-TRIP (v0.67.38)
-------------------------------------------------------
Render MIDI now includes the project's discrete MIDI Controller Lane events. Controller-only MIDI tracks are exported too, so controller data created or imported in Poor Man's Studio is no longer silently omitted from the user-facing MIDI file.

The exporter continues to write its established tick-zero setup controllers for useful external playback: CC7 track volume, CC1 modulation default, CC11 expression default, CC0/CC32 bank select, followed by Program Change. In user MIDI export, each generated setup controller is preceded by a Poor Man's Studio sequencer-specific meta marker that external MIDI consumers may ignore. On Poor Man's Studio re-import, only an exact immediately-following tick/channel/controller/value match is treated as generated setup and withheld from editable Controller Lane data. Project-authored CC at the same tick remains ordinary lane data and therefore becomes the final effective controller state after setup.

Malformed, missing, reordered, or nonmatching markers never suppress a controller message. They fail safe by importing the CC as ordinary project data. Internal preview/render MIDI remains marker-free and keeps its existing playback-oriented controller path.

Bank/program import now captures bank state at the effective Program Change instead of allowing later CC0/CC32 automation to retroactively change the imported initial instrument assignment. Later Bank Select CC remains normal editable Controller Lane data.

Stable controller-event IDs are project identity, not MIDI-file identity. MIDI export/re-import preserves tick/channel/controller/value semantics but assigns fresh project stable IDs after import. Project CC64 remains ordinary Sustain playback data and stays separate from TAKE REVIEW Apply CC64. Project format remains 16.

Not included in v0.67.38: live incoming CC recording, MIDI Learn, Program Change editing lanes, pitch bend/aftertouch lanes, 14-bit CC/NRPN/RPN, interpolation, or Take Review controller commit.

LIVE MIDI CONTROLLER RECORDING + TAKE REVIEW (v0.67.39)
-------------------------------------------------------
MIDI Input / Live Monitor / Record now adds Record Controllers = Off / All CC 0-127. Off is the default and preserves the earlier project-controller recording behavior. All CC 0-127 records incoming Control Change messages into the armed MIDI track through the existing transport-synchronized recording path. The same MIDI input channel filter applies to notes and controllers, and live monitoring forwards Control Change through the established VST3/CLAP instrument route rather than a second controller engine.

Recorded controller timing uses the exact project tick from the existing recording transport clock. Note Quantize and Controller Lane graphical Snap do not move recorded CC events. Multiple messages at the same track + channel + controller + tick collapse deterministically with the last real source value winning. A controller-only take is valid. When a recorded point collides with an existing project controller point, the existing project stable ID is retained; genuinely new points receive fresh stable IDs when committed.

Count-In controller movement is monitor-only. Punch records controller events only in [Punch In, Punch Out), including exact Punch In and excluding exact Punch Out. Loop Merge combines retained controller events across passes, with later pass values winning exact lane/tick collisions. Loop Takes = Review retains ordinary controller performances per pass as well as the already-existing special CC64 sustain metadata. Whole Pass audition/Keep includes the selected pass controller performance. Comp includes only real controller events from the pass selected for each [segment start, segment end) region; it does not synthesize a controller point at a Comp boundary. Controller-only Take Reviews are valid pending reviews.

CC64 intentionally may participate in two independent paths during one performance. With Record Controllers = All, the physical CC64 message can become ordinary project Sustain data; TAKE REVIEW Sustain Pedal = Apply CC64 can simultaneously retain the same pedal performance as note-duration interpretation metadata. These meanings remain separate. Panic's forced CC64 Up is retained as ordinary recorded project CC64 when controller recording is enabled, while normal Stop does not synthesize resets for unrelated controllers.

Undo Take / Redo Take now treats the take's notes, project controller vector, and pending Take Review as one atomic recording-history state. The independent Undo CC / Redo CC history remains separate. A take-history restore refuses to overwrite newer manual Controller Lane edits; undo those newer CC edits first, then the take-history operation can proceed.

Project format is now 17. Format 17 persists general retained controller events inside Active and Archived Take Review passes. Formats 9-16 remain load-compatible; a format-16 review loads with an empty retained-general-controller collection while preserving its existing notes, CC64 metadata, Comp configuration, archives, metadata, and project-level format-16 Controller Lane data. Snapshot Active, Duplicate Archive, Copy to Track, Move to Track, Archive, Restore, save/reopen, Whole Pass, and Comp all preserve the retained controller performance payload.

Not included in v0.67.39: MIDI Learn, Program Change recording/editor lanes, pitch bend, channel/poly pressure, 14-bit CC, NRPN/RPN, interpolation/smoothing, destructive replacement recording, AudioClip automation, simultaneous multitrack MIDI recording, or sample-accurate callback-loop redesign.
